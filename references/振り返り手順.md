# 振り返り手順（結果確定後ワークフロー）

予想の「工程0〜12」と対になる、結果確定後の固定工程 V0〜V7 ／ v2（v2でV6.5＝`reflection/` への回顧ファイル出力を追加）

**位置づけ：** 振り返りは予想と同じ重みを持つ工程であり、品質ゲート（V7）全✓で初めて完了とする。「当たった/外れた」の一括感想は振り返りではない。層ごとに成否を分離し、教訓を決まった出力先へルーティングすることで、(1) 成功していた層を壊す誤修正を防ぎ、(2) 教訓が指示やチャット記憶に散逸するのを防ぐ。

**起点：** 「振り返り」「回顧」「結果です」等でこの手順を発動。セッション冒頭の同期チェック（最新main取得→validate）は通常どおり先に行う。

**成立起源：** 七夕賞2026。全22ルール遵守で回収0となった初のケースで、(a) 層別に見れば馬場・展開・選定は成功で構造のみが失敗だったこと、(b) rule_fires の outcome 判定語彙が未定義で「逆効果」を誤認定しかけたこと、の2つが手順の明文化を要求した。

---

## V0. 事実確定（解釈より先に・必須）

1. **JRA公式を一次ソースとして取得**し、着順・配当（単複/馬連/ワイド/三連複/三連単）・コーナー通過順・**ハロンタイム**・上がり3F・**発表馬場**を確定する。**チャット記憶・予想時の想定からの転記は禁止**（過去に馬場・脚質・配当の誤記事故あり）。

   ```bash
   python3 tools/jra_result.py --date 2026-08-02 --course 札幌 --race 11
   ```

   これ1本で上記が揃う。**発表馬場は必ずこの出力で確定する**（二次ソースの当日ヘッダー表示と食い違った事故が関屋記念2026で1件。going を重で記録していたがJRA公式は不良だった）。**含水率・クッション値は結果ページに無い**ため、別途取得できなければ空欄＋「取得失敗」とする。収録範囲外（直近2か月より前）や地方・海外はツールが範囲を示して失敗するので、Yahoo競馬denma等の二次ソースへ切り替え、**どのソースで確定したかをnotesに残す**。
2. ユーザー貼付の結果表がある場合も、配当・通過順など欠けている項目は検索で補完する。
3. **取得に失敗した項目は空欄のまま「取得失敗」と明記**する。推測で埋めた瞬間にログ全体の信頼が死ぬ。後日の欠損穴埋め（自動トリガー）に委ねる。
4. 予想時データの誤り（馬番・枠・斤量・騎手の誤記）がなかったかを出馬表と突き合わせて確認し、あれば修正行を先に出す。

## V1. 的中判定・収支

- `bets.csv` の各行に hit / return を機械判定で付ける（paper でも同様に計算する）。
- 購入総額・回収額・レース収支を1行で宣言する。

## V2. 層別採点（5層 × ○△× ＋ 根拠1行）

「外れた」をひとまとめに反省しない。以下の5層に分離し、各層に ○／△／× と根拠1行を必ず付ける。

| 層 | 見るもの | 採点基準 |
|---|---|---|
| **L1 馬場読み** | 想定馬場・バイアス判定・前崩れトリガー成否 | 実馬場と宣言の一致＝○、部分一致＝△ |
| **L2 展開読み** | ペースシナリオ・逃げ馬の特定・隊列 | 本線パターン的中でも逃げ馬特定ミス等があれば△ |
| **L3 選定（印・紐プール）** | **3着内3頭のうち何頭が自分の紐プール（全券種の統合リスト）に入っていたか**を必ず数える。消し馬（✕）の着順。☆の成否 | 3/3捕捉＝○、2/3＝△、1以下＝×。✕馬が3着内なら1段階降格 |
| **L4 買い目構造** | プール捕捉を的中に変換できたか。軸の集中依存・券種間の紐リスト整合・列配置 | 捕捉していたのに構造で逃した場合はL3○・L4×と明確に分離する |
| **L5 ルール適用** | rules_master の followed 率。ゲートの機能 | 全遵守＝○。ただし全遵守で外れた場合は「台帳の穴」を探す義務が発生する（下記V5） |

**L3の「プール捕捉数」はこの手順の中心指標。** 選定（馬を見る力）と構造（買い方）は別の能力であり、混ぜて反省すると誤った箇所を直せない。

## V3. 反実仮想（hindsight bias ガード付き）

「どう買っていれば取れたか」を検証する。ただし以下のガードを厳守：

1. **使ってよい情報は発走前に確定していたものだけ**（最終オッズ・馬体重・実馬場宣言まで）。着順・配当・通過順を選定根拠に使うのは禁止（的中判定にのみ使う）。
2. 候補構造は**当時の台帳・配分表で正当化可能だった代替案に限る**。後知恵の「魔法の買い目」を作らない。
3. 各候補は点数を展開検算（R16）し、費用と予算適合を明記する。
4. 的中する反実仮想が見つかっても、それは n=1 の事実であって「その構造が常に優れる」証明ではない。**採用したければ V5 で仮説として登録し、n=10 レビューか backtest.py の券種比較で判定する。**

## V4. rule_fires の判定（2軸・capture と outcome）

**発火した全行に `capture` と `outcome` の2つを付ける**（2026-08-03改訂）。

### なぜ2軸か

改訂前は outcome の1軸だけで、発火117件中79件（68%）が「中立」に滞留し、「逆効果」は台帳全体で**0件**だった。結果としてR19の降格条件「逆効果≧効いた」が**構造的に発動しえず**、R20は発火6件・全中立で判定不能になった。原因は、outcome が損益寄与しか測っていないため「ルールが指した馬がたまたま結果に絡まなかった」と「ルールが正しく指していたのに買い方で取り逃した」が同じ `中立` に落ちることにある。

**capture＝予測方向の当否（損益と独立）／outcome＝損益寄与。** capture は「結果に照らしてルールが正しい向きを指していたか」だけを見るので、損益が動かなかったレースでも判定できる。

### V4-a. capture（rules_master の `direction` が入力）

| capture | 定義 |
|---|---|
| **的中** | 上向きに扱わせた馬が3着内／下向きに扱わせた馬が3着外＝向きが正しかった |
| **空振り** | 上向きに扱わせた馬が3着外。保全コストは出たが害はない（**降格根拠にならない**） |
| **逆行** | **下向きに扱わせた（除外・格下げ・回避させた）馬が3着内。ルールが結果と逆を向いた** |
| **方向なし** | `direction=手続き` のルール、または対象馬が存在しない |

- `direction` は台帳（`rules_master.csv`）に記録済み。`上向き`／`下向き`／`双方向`／`手続き` の4値
- `双方向`（構造分散系・R12 R23 R24 R28 R31 R32）は、分散先のいずれかが3着内なら `的中`、どれも来なければ `空振り`、分散を理由に落とした馬が3着内なら `逆行`
- **`direction=手続き` の行は必ず `方向なし`。** 検算・記録・工程順序・シナリオ制約は馬を指さないので、遵守率と validate.py での機械化可否で扱う（validate.py が不整合をWARNで検出する）
- **`空振り` を `逆行` に寄せない。** 逆行は「そのルールがなければ拾えていた馬を、ルールが落とした」ケースに限る

### V4-b. outcome（損益寄与・従来どおり）

| outcome | 定義 |
|---|---|
| **効いた** | ルールに従った行動が、的中・損失回避・誤り防止に実際に寄与した |
| **逆効果** | 従ったことが**原因で**的中を逃した／損失が出た。**V3の反実仮想で「従わなければ取れていた」ことを裏取りできた場合のみ**認定できる |
| **中立** | 結果に影響なし（判断が結果を左右しなかった） |

**迷ったら中立。** 逆効果の安易な認定は n=10 レビューでのルール誤降格に直結するため、認定基準を最も厳しくする。**中立が多いこと自体は問題ではない**（それが capture を分離した理由であり、ルールの良否は capture 側で測る）。

## V4.5 原因深堀り（批判的思考ゲート）

V2で×または△が付いた**全層**に対し、以下の固定4問に答える。○の層にはQ5のみ。
自由記述の反省文は禁止。各層の出力は「分類＋再発性＋ルーティング先」の3行以内。

**回答に使ってよい情報は発走前に確定していたものだけ**（V3と同じガード）。
「結果を見れば分かる根拠」をQ1に書いた時点でその層の深堀りは無効。

### ×・△層への固定4問

- **Q1 当時根拠：** その判断（宣言行・スコア・印）は発走前の何に基づいていたか。
  検索結果／計算／仮定のどれかを特定する（「なんとなく」は仮定として明記）
- **Q2 誤り分類（4択・必須）：**
  | 分類 | 定義 |
  |---|---|
  | (a) データ欠損 | 取るべき情報を取っていなかった |
  | (b) 解釈誤り | データはあったが読み違えた |
  | (c) 重み付け誤り | 読みは正しいが係数・配点が過小/過大だった |
  | (d) 手順逸脱 | ゲート・工程を飛ばした／簡略化した |
- **Q3 再発性：** 同じ入力・同じ手順でやり直したら同じ誤りが出るか。
  出る＝構造的、出ない＝偶然・ノイズ
- **Q4 検知可能性：** 予想確定前のどの工程で機械チェックできたか。
  できた工程を特定できない教訓はルール化できない

### ○層への1問

- **Q5 実力か幸運か：** その判断は別の馬場・展開シナリオでも成立していたか。
  幸運なら「成功層の過信」として仮説化候補（②）。成功の誤帰属も台帳の穴になる

### 分類→ルーティング対応表（V5への接続・必須）

| Q2分類 × Q3 | デフォルト出力先 |
|---|---|
| (a)欠損 × 構造的 | ① 取得を工程ゲート化する暫定ルール |
| (b)解釈 × 構造的 | ② 判定方法つき仮説（or ③ コース・馬固有なら該当ナレッジ）|
| (c)重み付け × 構造的 | ② のみ（R19により係数の即変更は禁止。n=10判定の仮説として登録）|
| (d)手順逸脱 | 新ルール不要。既存ルールの followed=0 として rule_fires に記録し遵守検証を優先 |
| いずれか × 偶然 | ④ 記録のみ（何もしない勇気）|

### 過剰生産ガード

- V4.5起点の**①ルール化提案は1回の振り返りで最大2件**。3件目以降は②へ降格する
- デフォルト対応表から外れるルーティングは可（理由1行必須）

## V5. 教訓のルーティング（4分岐 ＋ R19ガード）

見つけた教訓は、以下のいずれか**1つ**に必ずルーティングし、**追記先ファイル＋追記行をセットで出力**する。指示本体には書かない。

| 分岐 | 条件 | 出力先 |
|---|---|---|
| **① 暫定ルール** | 予想確定前のゲートで機械チェックできる失敗則 | `rules_master.csv` に R番号・origin_race・status=暫定(n=10判定) で追加 |
| **② 検証待ち仮説** | データを集めて判定すべき傾向・閾値・構造比較 | `log/README.md` の仮説節に、**判定方法を1行含めて**追加 |
| **③ ナレッジ追記** | コース・レース・馬の固有知見 | 補正表／レース別傾向／horse/ の該当ファイル |
| **④ 記録のみ** | 単発の偶然・ノイズと判断 | races.csv の notes に留める（何もしない勇気） |

**R19ガード：** n<10 で既存ルール・閾値を「変える／緩める／削る」のは禁止。許されるのは「追加（暫定）」と「仮説登録」だけ。

**全ルール遵守で外れた場合の特則：** 「ルールを守っても無意味」という結論は禁止。遵守済みなのに防げなかった＝**台帳に穴がある**サインとして、分岐①または②へ必ず1件以上ルーティングする。

## V6.5 回顧ファイル出力（`reflection/` へ1レース1ファイル・必須）

V0〜V7の内容とサマリーを **`reflection/<YYYY-MM-DD>_<レース名>.md`** として書き出す（例 `reflection/2026-08-02_アイビスサマーダッシュ.md`）。命名は `references/脚質認定_<日付>_<レース名>.md` と同じ規約。

**位置づけ：このmdは `log/*.csv` からの派生成果物であり、正本ではない。**
数値の正本はCSV（`analyze.py` の出力が正）、手順の正本は本ファイル。CSVとmdが食い違ったらCSVが正で、mdを直す。**mdにしか存在しない数値・判断を作らない**（4つ目の正本を作らないため）。

**`reflection/` は書き出し専用（read には使わない）。** 人間が後から結果と原因を確認するためのアウトプットであり、**工程の入力ではない**。予想・集計・較正レビュー・ルールの capture 判定・原因分析の根拠は、すべて `log/` 配下CSVと一次ソース（`tools/jra_result.py` 等）から取る。回顧mdを読みに行くのは、ユーザーが**回顧そのもの**を求めたとき（内容の照会・改訂・新規書き出し）だけ。
理由：正本でないファイルを判断の入力に回すと、CSVに無い数値・解釈が工程へ逆流し、4つ目の正本が事実上できる。書き出しの必須性（本節）と、入力にしないこと（本段落）は両立する。

**必須セクション（この順序・見出しを崩さない）：**

1. 冒頭サマリ表：`race_id` ／日付・R番号／格・コース・頭数／確定馬場／結果ソース／実購入と計画の差異／収支
2. **`## サマリー`（人間が最初に読む節・V0〜V7の後に書いて先頭に置く）** … 下記の5項目を各1〜4行で固定。工程の再掲ではなく**工程をまたぐ統合**を書く場所であり、V4.5の固定4問の枠に収まらない「層を横断する判断」はここにしか置き場がない
   - **結果と収支**：着順3頭・配当・購入/回収/収支を1行
   - **効いた層／外した層**：L1〜L5の○△×を平文で1行（例「馬場とルール遵守は○、展開と選定が×」）
   - **核心**：なぜ外した（当たった）かを**独立した原因に分解**し、各原因が単独で結果を変えられたかを明記する。原因が複数あるときは相互に独立かどうかを必ず書く（例「この2つは独立で、どちらか片方でも防げていれば軸に置けていた」）
   - **取れていた買い目**：V3で的中した反実仮想を1行（当時情報で正当化可・予算適合を併記）。なければ**「当時情報では取れなかった」と明記**する（後知恵の魔法の買い目を書かない）
   - **次の打ち手**：追加した①ルール・登録した②仮説・未処理事項を1〜2行
3. `V0 事実確定` … 着順（3着まではタイム・上がり・通過順・馬体重つき）・全着順・全配当・**取得失敗項目の明記**
4. `V1 的中判定・収支` … 券種ごとの構造・点数・費用・hit・return の表
5. `V2 層別採点` … L1〜L5の○△×と根拠1行（**L3にはプール捕捉 x/3 を必ず書く**）
6. `V3 反実仮想` … 候補構造・点数・費用・的中可否・当時情報での正当化可否の表
7. `V4 rule_fires 判定` … **capture（的中/空振り/逆行/方向なし）と outcome（効いた/中立/逆効果）を別々に**件数集計し、判定が割れた行の理由を書く
8. `V4.5 原因深堀り` … ×△層のQ1〜Q4、○層のQ5（**対応表から外れるルーティングは理由1行を併記**）
9. `V5 教訓のルーティング` … 分岐・内容・出力先の表＋R19ガードの宣言
10. `V6 ログ行` … 追記した6点セットの要約（CSVの全文は転記しない）
11. `V7 品質ゲート` … 全✓の確認と validate の ERROR/WARN 件数
12. `較正カウンタ` … n=X/10。n=10到達ならレビュー発動を明記
13. `次セッションのコミット確認対象` … 本振り返りで触ったファイルの列挙（自動トリガー「コミット確認」の入力になる）

**運用メモ：**
- 既存レースの遡及作成（バックフィル）は任意。作る場合は冒頭サマリに `※バックフィル` と明記し、当時の判断を再構成した箇所を区別する
- ペーパー予想も同様に作成する（V1のみ「paper・bets行なし」と書く）
- チャット出力とmdの二重管理を避けるため、**チャットでは要約、mdでは全文**とし、mdを成果物の置き場とする
