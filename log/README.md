# 予測ログ（検証基盤）

予想の精度・回収率を定量検証するためのログ。**レースごとに必ず記録し、10〜20レース単位で集計→ルール・閾値の調整に使う。**

## ファイル構成

| ファイル | 粒度 | 記録タイミング |
|---|---|---|
| `races.csv` | 1レース = 1行 | 予想確定時に前半、結果確定後に後半を記入 |
| `predictions.csv` | 1頭 = 1行 | 予想確定時（最終版の印・点数）＋結果確定後に着順 |
| `bets.csv` | 1券種 = 1行 | 購入時＋結果確定後に払戻 |
| `rules_master.csv` | ルール台帳 | ルール追加時 |
| `rule_fires.csv` | 1レース×1ルール = 1行 | 振り返り時 |
| `analyze.py` | 集計スクリプト | 任意（python3 analyze.py で実行） |
| `validate.py` | 検証スクリプト | 予想確定前・振り返り後に python3 validate.py（ERROR=ゲートFAIL級） |

## 記録の原則

1. **予想は「最終版」のみ記録する。** 途中の揺れは記録しない（軸の揺れ自体は rule_fires.csv の R06 で追跡）。
2. **予想確定時に predictions.csv を埋めてからレースを迎える。** 結果を見てから印を書くと検証にならない。
3. 不明な値は空欄のままにする。推測で埋めない。
4. 印は最終版の1頭1印。無印は `-`、消しは `x`。
5. **predictions.csv は原則、出走全頭を記録する。** 「無印で好走した馬」だけ後から書き足すと、無印・消しの成績が実際より悪く見えるバイアスが生じる（既走3レースのバックフィル分はこのバイアスを含むため、無印/消しの集計値は参考外とする）。
6. **予想確定時の predictions.csv は数値列（base_score / composite_coef / additive_total / r_adj / final_score / myomi_score / r_value）を全頭で記入する。** 空欄が残る状態はルールゲートFAIL扱いとし、印・買い目を確定しない（オッズ未確定によるR値・r_adjのみ「暫定確定」として空欄可、確定オッズ入手後に埋める）。R14（確定済み最終点を引用した照会回答）とanalyze.pyのR値帯別集計は、この列が埋まっていることが前提。バックフィル3レース（さきたま杯・函館記念・ラジオNIKKEI賞）の数値欠損は例外として集計上参考外。
7. **r_adjはモデルの目と市場（オッズ）の目を分離するための必須列。** final_score − r_adj がオッズ非依存の素点。base_breakdownは自由記述メモでゲート対象外だが、外れ馬の事後分析（どの主観要素が誤ったか）のために記入を推奨する。
7-b. **r_adjは「加算層に実際に適用した値」を記録する。** 確定オッズでR帯が変わっても
遡って書き換えない（監査痕跡の保全）。差分はnotesに「適用±X・確定帯±Y」と記す。
今後は確定オッズ入手時にR補正を再計算してからロックし、この差分自体をゼロに近づける。
8. **購入しないレースも全工程で予想し、ログを残してよい（ペーパー予想）。**
races.csv / predictions.csv / rule_fires.csv は通常どおり全記入、bets.csv のみ行を作らない
（cost=0行は券種別収支を汚すため禁止）。races.csv の notes 冒頭に「paper」と明記する。
較正カウンタ（n=10判定）・印別成績・R値帯・ルール遵守・backtest.py の券種リプレイは
すべてペーパー分を含めて集計する（backtest は predictions から買い目を再構成するため bets 不要）。

## 各CSVのカラム定義

### races.csv
- `race_id` : 一意ID（例 `2026_hakodate_kinen`）
- `date` / `race_name` / `grade` / `course`（例 `函館芝2000`）/ `field_size`
- `going` : 良/稍重/重/不良
- `cushion` : クッション値
- `pace_score_pre` : 枠順確定時のペーススコア（逃げ×2＋先行×1）
- `pace_flag_pre` : 事前フラグ（前残り/中立/前崩れ）
- `pace_actual` : 実際のペース（スロー/平均/ハイ）
- `pace_match` : 事前フラグと実際の一致（1/0）
- `bias_actual` : 当日実バイアス（内前/フラット/外差し）
- `result_1st` `result_2nd` `result_3rd` : 馬番
- `payout_sanrentan` / `payout_sanrenpuku` : 確定配当（円）
- `notes` : 自由記述。ペース密度（pace_score_pre÷field_size）を必ず併記する（検証待ち仮説6）

### predictions.csv
- `race_id` / `horse_no` / `horse_name`
- `mark` : ◎○▲△☆ / `-`（無印）/ `x`（消し）
- `base_score` : ベース点
- `base_breakdown` : ベース点の内訳メモ（例「相手関係A/持続適性/成長+」。1行でよい）
- `composite_coef` : 合成係数（クリップ後）
- `additive_total` : 加算層合計
- `r_adj` : 加算層のうちR補正の値（final_score − r_adj ＝ オッズ非依存のモデル素点）
- `final_score` : 最終評価点
- `myomi_score` : 妙味スコア
- `popularity` : 人気
- `win_odds` / `place_odds_max` : 単勝／複勝上限
- `r_value` : R値
- `finish_pos` : 着順（結果後）
- `in_place` : 複勝圏内 1/0（結果後）
- `notes`

### bets.csv
- `race_id` / `bet_type`（三連複/三連単/馬連/ワイド等）
- `structure` : 買い目の構造（例 `軸1頭 5→12,13,6,8,2,9`）
- `points` : 点数 / `unit` : 単価 / `cost` : 購入額
- `hit` : 的中 1/0 / `return` : 払戻額
- `notes`

### rules_master.csv
- `rule_id` / `rule_name` / `origin_race`（このルールを生んだレース）/ `added_date`
- `status` : 現行 / 暫定(n=10判定) / 包含済(RXX) / 廃止(YYYY-MM)。ゲートで個別チェックするのは現行＋暫定のみ。廃止は行削除せずstatus変更で残す（監査痕跡）

### rule_fires.csv
- `race_id` / `rule_id`
- `fired` : 該当場面があったか 1/0
- `followed` : ルールに従ったか 1/0
- `outcome` : `効いた` / `逆効果` / `中立` / `違反して失敗` / `違反したが結果OK`
- `notes`

## 集計で見る指標（analyze.py が出力）

- 印別の複勝率・平均着順・単勝/複勝回収率（◎○▲△☆別）
- 券種別の回収率
- ペーススコア事前フラグの的中率
- R値帯別（R≧4.0 / 3.0-4.0 / <1.5）の複勝率
- ルール別の遵守率と成績
- ベースライン比較（1番人気複勝ベタ買い／1〜3番人気複勝均等買いのROI）とシステム成績の対比
- r_adj分離：印別のfinal_score平均とr_adj平均（final_score−r_adj＝モデル素点の目安）

## 運用フロー

```
【予想確定「前」】ルールゲート：rules_master.csv の全ルールを全件チェックし、
  該当ルールの fired / followed を rule_fires.csv に予想時点で記入する。
  followed=0 のルールが1件でもあれば、印・買い目を確定せず修正する。
【買い目確定「直前」】ルールゲート②：暫定ルール全行＋買い目・配分・頭固定に作用する行を
  再チェックする。違反7件の大半が印確定後〜買い目構築中の裁量ドリフト
  （格下げ・軸移動・シナリオ矛盾）で発生したことへの構造対策。
  （※範囲を「R01〜R12」等と番号で書かない。台帳の全行が常に対象）
【予想確定時】races.csv 前半＋predictions.csv（全頭・評価点/R値込み）＋bets.csv を追記
【結果確定後】着順・配当・払戻・rule_fires.csv の outcome を記入
【コミット】UCHIYAMA が commit → Sync now
【10レース毎】python3 log/analyze.py / backtest.py で集計 →
  Claude.aiからは「バックテスト実行」でGitHub最新mainを直接取得して実行可
```

**ルールゲートの根拠：** バックフィル3レースで、ルール遵守2件はどちらも成功、違反6件はすべて失敗だった。事後の振り返りでは違反を防げないため、予想確定前の機械的チェックを必須工程とする。

## ルール・傾向データと結果が矛盾したとき

1. **即時には何も変えない。** 矛盾はrule_fires.csvのoutcome（逆効果/違反したが結果OK）として記録するだけ。予想セッション中のルール緩和の根拠には使わない（R19）
2. **改廃はn=10レビューで判定する。** R17適用（生成元レース除外）後の集計で、発火5件以上かつ「逆効果」≧「効いた」のルールを降格候補（現行→暫定）、暫定でさらに悪化したものを廃止とする。発火5件未満は判定保留（不運と誤りを区別できない）
3. **「違反したが結果OK」は違反の正当化に数えない。** 結果OKでも違反は違反としてカウントし、ルール側の反証としてのみ扱う
4. **ナレッジファイル（傾向・補正・血統）への反証は、該当ファイルに反証メモとして併記する**（元の記述は消さない）。例：「消しデータ：58kg以上0-0-0-10 ／ 反証：2026北九州記念で該当馬3着（1件）」。反証が2件溜まった傾向は妙味トラック以外での使用を停止し、n=10で存廃判定

## 較正カウンタ（振り返り毎に更新・レビュー発動の検知）

振り返りの最終ステップで、暫定項目ごとの現在サンプル数を1行で報告する：

較正カウンタ：全体 n=4/10 ｜ R12発火 3件 ｜ R13(G1) 0/10 ｜ 半減版帯域ズレ 0回 ｜ ☆的中 1/3

- 全体 n=10 到達 → analyze.py / backtest.py を実行し、R19 の手順（発火5件以上・逆効果≧効いた で降格）で暫定ルールと検証待ち仮説1〜8を一括判定する
- R13 は G1 レースのみでカウント（別トラック）
- カウンタ報告のないレビュー・振り返りは未完成として扱う

## 検証待ち仮説（n=10 到達時に判定）

バックフィル3レースから浮かんだが、母数不足のため暫定扱いの観察。

1. **勝ち馬は◎（地力1位）でなく「条件適合1位」に出る**（3/3で◎以外が勝利：○②・無印②・○⑬）。R12（三連単の頭◎○両置き）はこの暫定対策。n=10で◎と○の勝率を比較し、恒久化か廃止かを判定。
2. **▲の不振**（複勝圏0/2・平均11着）。▲の選定基準（3着内なら頭まで）が機能していない可能性。
3. **☆はR≧4.0裏付けありのみ機能**（ディール⑧成功、R裏付けなしの☆は複勝圏外）。妙味スコアのRトリガー重み引き上げ候補。
4. **ペーススコア中立（4〜6）はフラグとして情報量が薄い**（的中1/2、外れは「スローの質」の誤読）。中立時はR04の並列シナリオを必須とする現行運用で様子見。
5. **夏ローカルハンデG3は人気信頼度が構造的に低い**（北九州記念：2人気複勝率10%・勝ち馬半数が6人気以下、函館記念2026：1人気13着）。G1レジーム（頭堅い・紐荒れ）とは別物として、夏は妙味トラック重視・☆最低2頭確保で運用し、log実測で検証。
6. **ペーススコアは頭数・距離で非正規化。** races.csv notes にペース密度（スコア÷頭数）を併記し、n=10で閾値の頭数・距離依存を判定する（特に短距離戦）。
7. **荒れ度スコアは配当項と構造項（ハンデ/夏/頭数）が共線。** 宣言行に「構造項半減版スコア」を併記し、帯域判定がずれた回数をn=10で照合する。
8. **R≧4.0妙味は複勝上限使用による小プールの幅アーティファクトを含む疑い。** predictions.csv notesに複勝下限も記録し、上限/下限比とR妙味の的中を照合する。
9. 夏ローカルハンデG3で58.0kg以上は軸・頭に据えない（七夕賞2026で58kg2頭が7着・10着。函館記念R10と同型か）。判定：七夕賞・小倉記念・新潟記念の過去10年で58kg以上の複勝率を集計
10. 逃げ馬の特定を主観でなく「直近5走で単独ハナを取った回数」で機械判定する（七夕賞2026で⑪アスクナイスショーの逃げ＝迎春S逃げ切りを見落とし、単騎逃げ候補を③のみと誤認）。判定：n=10まで両方式を併記し特定精度を比較
11. 荒帯域では三連単Fより三連複BOX（印＋妙味閾値到達馬）が構造的に頑健（着順指定は第2の集中リスク。七夕賞2026では印6頭+⑥のBOX35点=3,500円が唯一の予算内的中構造だった）。判定：backtest.pyの券種比較（Phase 2タスクと統合）
