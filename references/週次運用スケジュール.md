# 週次運用スケジュール v1 — 予想ルーティンとパターン切替

> **位置づけ：本ファイルは工程・ゲートを一切変えない。** 予想の正本は『プロジェクト指示_v2.md』（工程0〜12）、振り返りの正本は『振り返り手順.md』（V0〜V7）のまま。本ファイルはそれらを**「いつ・どの順で回すか」**に落とした運用カレンダーであり、週の開催パターンに応じてルーティンを切り替えるための管理台帳。

## 2. 標準ルーティン（1レースの基本形）

```
準備（`#準備`・週1回・レース横断・特別登録公開後＝月〜火）
  ├ セッション冒頭同期チェック（最新main→validate.py→指示差分）
  ├ 今週のパターン宣言（A/B/C/D）＋対象レースの確定（本予想 or paper）
  ├ 各レースの予算宣言（1レース3,000円上限・記録の原則9）
  ├ 未整備ナレッジの**検知のみ**（コース系・出走馬プロファイルとも、収録は `#収録` へ回す）
  └ **実行計画表の出力（必須）**：今週打つ全プロンプトを
     「曜日｜プロンプト｜対象｜チャット」の表で宣言する（下の記入例参照）。
     順序は枠順確定の早い順→ナレッジ整備済みの順

収録（`#収録`・別チャット・枠順不要）
  ├ コース系（開催替わり時のみ・コース単位）：コース補正表（未収録なら C0〜C6）／
  │   レース別傾向データ＋配当レンジ欄／血統D節／騎手C節
  ├ **出走馬プロファイル（毎レース必須・レース単位）**：全頭の脚質機械認定＋主観併記＋
  │   5走距離帯＋父・母父＋斤量＋馬場別集計（正本『脚質認定ルール.md』§1・§1-b・§6）。
  │   想定メンバー公開後〜枠順確定前（火〜水目安）に実行する。
  │   ◎○候補になりうる上位人気馬は全キャリアまで深掘り
  └ 工程1（荒れ度スコア算出）以降は予想セッションに残す

実行計画表の記入例（パターンA・日曜重賞1本）：

| 曜日 | プロンプト | 対象 | チャット |
|---|---|---|---|
| 火 | `#収録 種別:出走馬プロファイル` | ○○記念 | 別チャット |
| 金 | `#予想` | ○○記念 | 新規 |
| 金 | 独立検証（評論エージェント） | ○○記念 | 別チャット |
| 日 | `#更新`（朝・締切前の最大2回） | ○○記念 | 予想と同 |
| 月 | `#振り返り` | ○○記念 | 新規 |

予想セッション（枠順確定後・1チャット1レース）
  ├ 工程0〜12を1回の応答で完走（完走原則）
  ├ オッズ未確定分は「暫定確定」：R値・r_adj空欄可、notesに暫定明記
  └ ログ追記行を出力 → UCHIYAMAがコミット → Sync now

独立検証（`予想評論_エージェントルール.md`・**重賞は毎回・必須**・2026-08-03格上げ）
  ├ **別チャット（新しいコンテキスト）**で実行する。同一コンテキストの自己批評では代替しない
  ├ タイミングは**予想セッションの直後〜買い目最終確定の前**（印は出ているが確定前）
  ├ 出力は「一致＝簡潔」「割れた箇所＝厚く」。割れた論点を予想側へ戻す
  └ 反映は `#更新` の再評価範囲に従う。**評論で割れたこと自体は範囲を広げる理由にならない**（R08）
     → 範囲外の変更が要ると判断したら「範囲外につき要 `#更新 全面`」で止める
  ※ paper予想では任意（工数ガード）。実購入するレースは必須

当日運用（発走前）
  ├ 朝：天気・馬場（含水率・クッション値）確認
  │   予報が前日から変化 → 工程3やり直し＋展開2パターンとの整合再確認
  ├ 前レース実馬場・バイアス確認 → 本線シナリオの確定 or 反転
  ├ 馬体重確認（+12以上は要確認）
  ├ 締切前オッズでR値再計算 → r_adjロック
  └ ルールゲート②（再チェック）→ 買い目最終確定 → 購入

結果確定後
  ├ 着順・配当・通過順・馬場をJRA公式検索で確認（記憶転記禁止）
  └ 結果欄の追記行を出力 → コミット

振り返り（原則レース翌日〜月曜）
  ├ V0〜V7（品質ゲートV7全✓で完了）
  ├ rule_fires.csv の outcome 確定
  ├ 較正カウンタの現在値を報告（n=10到達なら較正レビュー発動宣言）
  └ コミット → 次セッション冒頭で反映確認
```

## 3. 週パターン別スケジュール

その週の重賞配置に応じて、以下のいずれかを宣言してから動く。宣言フォーマット：

> **今週のパターン：C（土日各1本）／本予想：小倉記念／paper：関屋記念**

### パターンA：日曜重賞1本（最頻・標準）

| 曜日 | やること |
|---|---|
| 月〜火 | 準備（同期チェック・対象確定・未整備検知・実行計画表） |
| 火〜水 | **出走馬プロファイル収録**（`#収録`・別チャット・全頭）。未整備コースがあれば C0〜C6 を先行 |
| **金** | 枠順確定 → **予想セッション**（工程0〜12・暫定確定。プロファイル存在が前提）→ コミット |
| 土 | （任意）前日オッズでR値暫定更新。同競馬場の土曜レースで馬場傾向を観察 |
| **日** | 当日運用 → 購入 → 結果確定後の追記行 |
| 月 | **振り返り**（V0〜V7）→ コミット |

### パターンB：土曜重賞1本

| 曜日 | やること |
|---|---|
| 月〜火 | 準備（実行計画表まで） |
| 火〜水 | 出走馬プロファイル収録（`#収録`・別チャット・全頭） |
| **木** | 枠順確定 → **予想セッション**（プロファイル存在が前提） → コミット |
| 金 | （任意）前日オッズ更新 |
| **土** | 当日運用 → 購入 → 結果追記 |
| 日〜月 | **振り返り** → コミット |

### パターンC：土日各1本

| 曜日 | やること |
|---|---|
| 月〜火 | 準備（2レース分の対象確定・未整備検知・実行計画表をまとめて） |
| 火〜水 | 出走馬プロファイル収録（**1レース1チャット**で2本） |
| **木** | 土曜分の枠順確定 → **土曜分の予想セッション** |
| **金** | 日曜分の枠順確定 → **日曜分の予想セッション**（別チャット） |
| **土** | 土曜分の当日運用 → 結果追記。日曜分の馬場材料（土曜実馬場）を観察 |
| **日** | 日曜分の当日運用 → 結果追記。土曜分の振り返り着手可 |
| 月 | 両レースの**振り返り**（レース毎に実施）→ まとめてコミット |

土曜の実馬場・バイアスは日曜分の工程3上書き材料として必ず引き継ぐ（夏開催は移行が速いため特に）。

### パターンD：同日複数重賞（夏3場開催など）

1. **優先順位を先に宣言する**：本予想（実購入）は原則1本、残りはpaperか見送り。判断基準は「ナレッジ整備済み＞未整備」「重賞格＞OP」「予算枠」
2. **1レース＝1予想チャット**を厳守（コンテキスト分離。二重予想プロトコルの独立性と同じ理由）
3. 予想順序は発走時刻の早い順ではなく**枠順確定の早い順→ナレッジ整備済みの順**。時間が足りない場合はpaper側を工程完走のまま優先度下げ（部分実施の中途半端なログは残さない：やるなら完走、やらないなら見送り）
4. 荒れ度帯域・買い目配分は**各レース独立**に配分表を適用。購入額は**1レース3,000円上限**（`log/README.md` 記録の原則9）をレースごとに守る

### 工数上限（共通ガード）

- 本予想＋paperで**週1〜2本**が標準ペース（ロードマップPhase 0の設計値）。3本以上は較正カウンタ加速が必要な場合のみで、品質（工程完走・V7全✓）を落としてまで本数を増やさない
- 開催替わり週はコース収録（C0〜C6）が先行するため、予想本数を1本に絞ってよい

## 4. マネジメント（`#準備` セッション・毎週の管理チェック）

週初（準備セッション冒頭）に以下を確認する。指示v2の自動トリガーと同じ内容の**週次版チェックリスト**：

- [ ] 最新main取得 → `validate.py` ERROR 0
- [ ] 前週の追記行・修正行がコミット済みか（未反映なら再掲）
- [ ] 較正カウンタの現在値（`log/README.md`正本）と n=10 までの残数
- [ ] 直近7日以内のログ追記があるか（なければpaper候補を提示）
- [ ] 今週のパターン宣言（A/B/C/D）＋本予想/paperの割当
- [ ] 開催替わりの有無（未整備コース検知）
- [ ] **実行計画表の出力**（今週の全プロンプト×曜日×チャット。§2の記入例形式・省略不可）

### モデル切替（役割分担の週次適用）

- **Sonnet（通常運用）**：本スケジュールの全ルーティン（準備・予想・当日・振り返り・paper）
- **Opus（切替イベント）**：n=10到達 →「較正レビュー」／開催替わりのナレッジ拡充・工程変更を伴う設計 →「設計セッション」。切替は入口の固定フレーズで行う

### 予算管理

- 購入上限は**1レースあたり3,000円**（`log/README.md` の予算ガードが正本）。券種数・帯域・レース数を理由に増額しない
- 配分（堅実:穴）はレース毎に荒れ度帯域表へ機械的に従う。システムの好調・強気化を理由に上限を動かさない（ロードマップ・ガードレール4）
