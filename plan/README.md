# plan/ — 収録計画（`#準備` の保存先・`#収集` の入力）

**作業台帳であり正本ではない。** 正本は `references/` と `log/*.csv`。STATE.md と同じ扱いで、週が終わったら消してよい。

- `#準備 <対象週>` が収録ギャップ表の「未」「要作成」を、ノード（1ノード＝1PR）に変換して `plan/<週>.json` に保存する
- `#収集 <レース名>` が `python3 tools/plan_check.py plan/<週>.json --race <レース名>` で実行順を出し、鎖ごとにサブエージェントへ渡す
- 計画は `#準備` のあとで書き換えない。進み具合は PR の状態（gh）から取り、ファイルに書き戻さない

## 書式

```json
{
  "week": "2026-W44",
  "created": "2026-10-26",
  "nodes": [
    {
      "id": "tokyo-turf2000-course",
      "race": ["天皇賞（秋）"],
      "kinds": ["コース補正表", "血統D節", "騎手C節"],
      "files": ["references/コース別_脚質枠_補正表.md", "references/血統データ_扱いルール.md", "references/騎手データ_扱いルール.md"],
      "reserve": {"references/コース別_脚質枠_補正表.md": "㉝", "references/血統データ_扱いルール.md": "㉙"},
      "depends_on": [],
      "prompt": "#収録 東京芝2000 種別: コース補正表 / 血統D節 / 騎手C節\n※新規。対象レース：天皇賞（秋）（11/1）"
    },
    {
      "id": "tenno-sho-autumn-race",
      "race": ["天皇賞（秋）"],
      "kinds": ["レース別傾向", "配当レンジ"],
      "files": ["references/レース別_過去傾向データ.md"],
      "reserve": {"references/レース別_過去傾向データ.md": "㊳"},
      "depends_on": ["tokyo-turf2000-course"],
      "prompt": "#収録 天皇賞（秋） 種別: レース別傾向 / 配当レンジ"
    },
    {
      "id": "tenno-sho-autumn-profile",
      "race": ["天皇賞（秋）"],
      "kinds": ["出走馬プロファイル"],
      "files": ["references/脚質認定_2026-11-01_天皇賞（秋）.md"],
      "depends_on": [],
      "gate": "想定メンバー公開後",
      "prompt": "#収録 天皇賞（秋） 種別: 出走馬プロファイル\n※全頭必須（『脚質認定ルール.md』§1・§1-b・§6）"
    }
  ]
}
```

| キー | 内容 |
|---|---|
| `id` | `[a-z0-9-]`。ブランチ名 `claude/collect-<week>-<id>` に使う |
| `race` | このノードを必要とするレース名（複数可。`#収集` の引数と完全一致で引く） |
| `kinds` | ギャップ表の種別 |
| `files` | 書き込むファイル。**同じファイルに書くノード同士は必ず `depends_on` で順序をつける**（並列で追記すると番号と末尾追記が衝突する） |
| `reserve` | 新しく振るエントリ番号（ファイル→番号）。`#準備` の時点で既存見出しの次番号を予約する |
| `depends_on` | 先にマージ（または PR 作成）されている必要があるノード。例：レース別傾向は補正表エントリを要約するので、コース系に依存する |
| `gate` | 実行の前提（任意）。満たしていなければエージェントは PR を作らず「要作成（未公開）」で返す |
| `prompt` | 収録ギャップ表から作った `#収録` フレーズ（従来どおり、貼るだけで単独でも走らせられる形） |

`python3 tools/plan_check.py plan/<週>.json` の ERROR が 0 になるまで、`#準備` が計画を直す。
