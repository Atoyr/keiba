# 予測ログ（検証基盤）

予想の精度・回収率を定量検証するためのログ。**レースごとに必ず記録し、10〜20レース単位で集計→ルール・閾値の調整に使う。**

## ファイル構成

| ファイル | 粒度 | 記録タイミング |
|---|---|---|
| `races.csv` | 1レース = 1行 | 予想確定時に前半、結果確定後に後半を記入 |
| `predictions.csv` | 1頭 = 1行 | 予想確定時（最終版の印・点数）＋結果確定後に着順 |
| `bets.csv` | 1券種 = 1行 | 購入時＋結果確定後に払戻 |
| `rules_master.csv` | ルール台帳 | ルール追加時 |
| `rule_fires.csv` | 1レース×1ルール = 1行 | 振り返り時 |
| `analyze.py` | 集計スクリプト | 任意（python3 analyze.py で実行） |
| `validate.py` | 検証スクリプト | 予想確定前・振り返り後に python3 validate.py（ERROR=ゲートFAIL級）。スキーマ／数値ゲート／印の頭数(R15)／積み上げ検算／点数×単価(R16)／宣言タグと実購入の突合／**印と買い目の整合**（記録原則4）／**一次ソース未確認の `going`**（`馬場ソース=` 欠落）／**係数・加算層の分解整合**（記録原則10）／**capture と direction の整合**（記録原則11）／**適性タグの有無と `5走距離帯=` の要素書式**（A-3・A-3b）／**R25発火対象の精査記録**（A-4） |
| `backtest.py` | 戦略リプレイ | 任意。券種リプレイに加え、**三連複の軸候補5通り（◎／妙味最上位／最終点2位／最終点3位／当日1番人気）を同一レース・同一相手で対戦比較**（仮説12の判定入力・帯域別） |
| `calibrate.py` | 確率較正 | 任意。`final_score − r_adj`（モデル素点）→ 複勝確率のロジスティック較正。**単位は頭**。パラメータ2個・レース単位1レース抜きCV。市場（log単勝オッズ）を基準線として同時に出す |

## 記録の原則

1. **予想は「最終版」のみ記録する。** 途中の揺れは記録しない（軸の揺れ自体は rule_fires.csv の R06 で追跡）。
2. **予想確定時に predictions.csv を埋めてからレースを迎える。** 結果を見てから印を書くと検証にならない。
3. 不明な値は空欄のままにする。推測で埋めない。
4. **印は最終版の1頭1印。無印は `-`、消しは `x`（`✕` は使わない・validate.py がWARN）。**
   印は『競馬予想_評価ルール.md』第8項の区分に対応する：軸=◎（○）／対抗=○▲／押さえ=△／消し=`x`。
   **消しは「買い目に一切採用しない馬」の宣言であり、`bets.csv` の買い目に含まれる馬に付けてはならない**
   （validate.py がERROR）。R09で頭固定だけ外して複勝圏に残す馬は消しではなく押さえ＝`△`。
   押さえ相当が`△`の1頭を超えたときは、あふれた分を無印 `-` とし理由を notes に残す
   （`△` を1頭に制限しているのはR15であり、区分としての押さえは複数を想定している）。
5. **predictions.csv は原則、出走全頭を記録する。** 「無印で好走した馬」だけ後から書き足すと、無印・消しの成績が実際より悪く見えるバイアスが生じる（既走3レースのバックフィル分はこのバイアスを含むため、無印/消しの集計値は参考外とする）。
6. **予想確定時の predictions.csv は数値列（base_score / composite_coef / additive_total / r_adj / final_score / myomi_score / r_value）を全頭で記入する。** 空欄が残る状態はルールゲートFAIL扱いとし、印・買い目を確定しない（オッズ未確定によるR値・r_adjのみ「暫定確定」として空欄可、確定オッズ入手後に埋める）。R14（確定済み最終点を引用した照会回答）とanalyze.pyのR値帯別集計は、この列が埋まっていることが前提。バックフィル3レース（さきたま杯・函館記念・ラジオNIKKEI賞）の数値欠損は例外として集計上参考外。
7. **r_adjはモデルの目と市場（オッズ）の目を分離するための必須列。** final_score − r_adj がオッズ非依存の素点。base_breakdownは自由記述メモでゲート対象外だが、外れ馬の事後分析（どの主観要素が誤ったか）のために記入を推奨する。
7-b. **r_adjは「加算層に実際に適用した値」を記録する。** 確定オッズでR帯が変わっても
遡って書き換えない（監査痕跡の保全）。差分はnotesに「適用±X・確定帯±Y」と記す。
今後は確定オッズ入手時にR補正を再計算してからロックし、この差分自体をゼロに近づける。
8. **購入しないレースも全工程で予想し、ログを残してよい（ペーパー予想）。**
races.csv / predictions.csv / rule_fires.csv は通常どおり全記入、bets.csv のみ行を作らない
（cost=0行は券種別収支を汚すため禁止）。races.csv の notes 冒頭に「paper」と明記する。
較正カウンタ（n=10判定）・印別成績・R値帯・ルール遵守・backtest.py の券種リプレイは
すべてペーパー分を含めて集計する（backtest は predictions から買い目を再構成するため bets 不要）。
9. **予算ガード（1レース上限3,000円・2026-07-27制定）。** 1レースの実購入総額の上限は
**3,000円**とする。券種数・帯域・レース数を理由に増額しない。システムの好調や回収率の
上振れも増額の根拠にしない（ロードマップ・ガードレール4）。`races.csv` の `予算=` タグは
3,000以下で宣言し、`bets.csv` の cost 合計がこれを超えないこと。**制定日より前のレースは
対象外**（ラジオNIKKEI賞5,100円・北九州記念9,000円・小倉記念7,300円は制定前の記録として保持）。
10. **係数・加算層は分解して記録する（2026-08-03制定・A-1）。** `composite_coef` の内訳を
`coef_breakdown`、`additive_total` の内訳を `additive_breakdown` に書く。合成後の1値しか
残らないと、どの項が最終点を動かしたかを事後に復元できず、**係数アブレーション（第1回較正
レビューの構造課題B「最終点の序列が勝ち馬を捉えていない」の唯一の解法）が実行不能**になる。
起点はアイビスサマーダッシュ2026で、base全頭1位の⑥に適用した内枠ミスマッチ0.85が
`reflection/` のmdにしか残らずCSVから復元できなかった事故。**`reflection/` は書き出し専用で
工程の入力にしないため（`プロジェクト指示_v2.md` V6.5）、mdにしか無い値は事実上失われる。**
**制定日より前のレースは対象外**
（遡及入力は当時の内訳の再構成＝捏造になるため行わない）。
11. **rule_fires には `capture`（予測方向の当否）を `outcome`（損益寄与）と別に記録する
（2026-08-03制定・A-2）。** 旧来の outcome だけでは発火117件中79件（68%）が「中立」に滞留し、
R19の降格条件「逆効果≧効いた」が**構造的に発動しえなかった**（逆効果は台帳全体で0件）。
capture は損益と独立に、結果に照らして**ルールが正しい向きを指していたか**だけを見る。
制定日より前の行は空欄のまま（遡及付与は振り返り単位で行う）。
12. **未経験条件（当該距離帯・コースの実戦がない）は「不利」ではなく「未知」として扱い、
記録と発火だけを義務づける（2026-08-17制定・A-3／札幌記念2026の `#設計`）。**
台帳には既に条文がある——『血統データ_扱いルール.md』A節「距離延長/短縮が血統的に後押し＝**+1〜2**」
「**『初めての条件』を評価するときに血統が最も効く**」、同C節「母父（BMS）補正 **±0〜+2**」——が、
`predictions.csv` 187行中、母父の記載は**1行**・`5走距離帯=` タグは**0行**で、
札幌記念2026では16頭の `additive_breakdown` に血統項・距離項が**1件もなかった**。
**欠けていたのは条文ではなく発火と記録である。** したがって新しい閾値は作らず（R19）、
(a) 適性タグの記録（本節 base_breakdown・validate.py A-3）、
(b) 未経験馬に対する適用可否の1行記録（**R38**）、
(c) 加点幅の判定（**仮説22**・群2）の3層に分ける。
**±0 も正当な結論**であり、R38は加点を強制しない（記録を強制する）。
起点：札幌記念2026の◎⑩アドマイヤテラ（近5走 3200/3000/2500/2400/2400m＝**2000m以下ゼロ**、
キャリア最短2200mで芝2000mの出走歴なし。base84＝16頭中1位・2位に8点差を長距離実績のみで作り9着）。

## 各CSVのカラム定義

### races.csv
- `race_id` : 一意ID（例 `2026_hakodate_kinen`）
- `date` / `race_name` / `grade` / `course`（例 `函館芝2000`）/ `field_size`
- `going` : 良/稍重/重/不良
- `cushion` : クッション値
- `pace_score_pre` : 枠順確定時のペーススコア（逃げ×2＋先行×1）
- `pace_flag_pre` : 事前フラグ（前残り/中立/前崩れ）
- `pace_actual` : 実際のペース（スロー/平均/ハイ）
- `pace_match` : 事前フラグと実際の一致（1/0）
- `bias_actual` : 当日実バイアス（内前/フラット/外差し）
- `result_1st` `result_2nd` `result_3rd` : 馬番
- `payout_sanrentan` / `payout_sanrenpuku` : 確定配当（円）
- `notes` : 自由記述。ペース密度（pace_score_pre÷field_size）を必ず併記する（検証待ち仮説6）。**冒頭に宣言タグ（下記）を置く**

#### 宣言タグ規約（races.csv の notes 冒頭・validate.py の突合対象）

買い目の宣言（帯域・配分・予算）と実装（bets.csv）の乖離を機械検出するため、notes 冒頭に以下を1行で置く。書式は `キー=値` を ` / ` 区切り。

```
band=中 / 荒れ度=5 / 券種=三連複+三連単F / 堅実穴=40:60 / 予算=2500 / 計画総額=2400
```

| タグ | 内容 | validate の扱い |
|---|---|---|
| `band` | 荒れ度帯域（低/中/高） | 未決レースで bets があるのに欠落 → **ERROR** |
| `荒れ度` | 荒れ度スコアの数値 | 記録のみ |
| `券種` | 計画した券種を `+` 連結 | bets の bet_type 集合と不一致 → **ERROR**（`乖離理由=` があれば WARN） |
| `堅実穴` | 予算比（例 `40:60`） | bets.notes の `side=` が全行揃っていれば実配分と比較し、10ポイント超の差で WARN |
| `予算` | 宣言予算（円） | 実購入合計が超過 → **ERROR** |
| `計画総額` | 計画した購入総額（円） | 実購入合計と不一致 → **ERROR**（`乖離理由=` があれば WARN） |
| `乖離理由` | 計画と実購入がずれた理由 | 券種欠落・金額差を WARN に降格する唯一の手段 |
| `馬場ソース` | `going` を確定させた一次ソース（例 `JRA公式(jra_result.py)発表馬場芝良`） | notes に取得失敗/ブロック/据え置き/未確認の語があるのにこのタグが無く `going` が埋まっていると **WARN**（値に `/` `／` 空白 読点は使えない） |

- **無断の乖離は ERROR。** 買わなかった券種・減額は必ず `乖離理由=` を書く（計画4券種→実購入3券種、計画9,800円→実購入1,200円という過去2件の事故がこのチェックの起点）
- **`going` は一次ソースで確定させる。** 関屋記念2026で二次ソースの表示を採らず `going=重` と記録したが、JRA公式の発表馬場は**不良**だった（2026-08-02にjra_result.pyで訂正）。取得失敗を記録に残したまま `going` を埋めるのは、空欄より悪い（誤りが確定値として集計に入る）。`python3 tools/jra_result.py --date <日付> --course <場> --race <R>` で確認し `馬場ソース=` を残す
- `going` に確定値を入れたまま notes に「未確定/暫定」と書き残すのは WARN（どちらかに揃える）
- **bets.csv の notes** には `side=堅実` または `side=穴` を付ける（配分チェックの入力）
- **rule_fires.csv の notes** には判定時に参照した馬場を `as_of=重` の形で残す。確定 `going` と不一致なら WARN（旧前提のnotes残存を検出）。
  `as_of=良(確定)` `as_of=重(暫定)` のように但し書きを付けてよい（validate.py は先頭の馬場語だけを取り出して突合する・2026-08-02）

### predictions.csv
- `race_id` / `horse_no` / `horse_name`
- `mark` : ◎○▲△☆ / `-`（無印）/ `x`（消し＝買い目に採用しない馬。記録原則4）
- `base_score` : ベース点
- `base_breakdown` : ベース点の内訳メモ（例「相手関係A/持続適性/成長+」。1行でよい）。
  **末尾に近5走の成績タグを機械可読で併記する**（2026-08-09導入・**2026-08-17に馬場と格を追加**・仮説20/23の判定入力）：

  ```
  5走距離帯=1600:稍重:6着:G3;1600:稍重:4着:G3;1600:良:1着:3勝;1600:良:7着:3勝;1600:良:1着:2勝
  ```

  書式は `5走距離帯=` に続けて **`距離:馬場:着順:格`** を `;` 区切りで**近走順**に並べる。
  距離は m の数値のみ（`1600`）、馬場は `良` `稍重` `重` `不良`、着順は `6着` の形、
  格は `G1` `G2` `G3` `L` `OP` `3勝` `2勝` `1勝` `未勝利` `新馬` `地方` `海外`。
  競走中止・除外は着順欄に `除外` `中止` と書き、キャリアが5走未満ならある分だけ書く。
  **取れない項は `不明` と書く**（要素数は常に4つに揃える・推測で埋めない）。

  **馬場と格を足した理由（2026-08-17・中京記念2026の `#設計`）：**
  準備工程は既にこの情報を**取得している**——『脚質認定ルール.md』§1「入力データ」は近5走について
  「通過順／頭数／**距離・コース**／**馬場**」の取得を規定し、§4の補正条文も距離差・馬場を前提に書かれている——が、
  同 §6「出力形式」が 4角相対位置・r_med・IQR・単独ハナしか書き出さないため、
  **距離と馬場が変換の途中で捨てられ、予想工程に届いていなかった**（`references/脚質認定_*.md` 4ファイルとも
  同じ10列で距離・馬場の列を持たない＝仕様どおりの挙動であって単発の記入漏れではない）。
  起点は中京記念2026の2着⑤ミニトランザット（当日5番人気・final 63.0＝16頭中9位・**無印**）。
  同馬は **芝1600が11戦中9戦[4-0-1-4]／良[4-0-2-2]・稍重[0-0-0-3]／中京芝1600に1勝クラス勝ち**で、
  base62 の唯一の根拠だった**前走しらさぎS6着は稍重での凡走**だった。
  **格を併記するのは R25 の発火対象（base70未満 かつ 1年内に重賞4着以内）を機械抽出するため**で、
  R25 は現行ルールにつき**条文は変更しない**（「チェックの置き場所の原則」に沿った既存ルールの機械化）。
  **拡張時点で本タグの使用実績は0行・`SCHEMA_V3_FROM` 以降のレースも0件のため、移行も遡及も発生しない。**
  **自由記述メモ本体は従来どおり自由**で、このタグだけを機械可読にする（列は追加しない）。
  **理由（仮説20）：** 工程2の5走スキャンが距離帯を区別しないため、「向かない距離での大敗」が
  そのままベース点を押し下げる疑いがあるが、`base_breakdown` が自由記述で**距離が機械可読でないため
  現在のログでは層別できない**。CBC賞2026の1着②フロムダスク（base60・最終点18頭中16位。不足11.5点は
  係数・加算層を全て上振れさせても埋まらず base層が支配項）が起点。
  **遡及入力はしない**（当時の内訳の再構成になるため。記録原則10と同じ扱い）。
  **タグ欠落は 2026-08-17 以降のレースで validate.py が WARN を出す（A-3）。**
  当初は「運用で担保する」としていたが、2026-08-09の導入後 CBC賞・中京記念・札幌記念の3レース
  すべてで記入されず **187行中0件**だった。「チェックの置き場所の原則」（機械判定できるものは
  validate.py）に従い機械化した（札幌記念2026の `#設計`）。**遡及入力はしない。**

  **あわせて父・母父を機械可読で併記する（2026-08-17〜・A-3）：**

  ```
  5走距離帯=3200:3着;3000:1着;2500:11着;2400:中止;2400:4着 / 父=キタサンブラック / 母父=ブライアンズタイム
  ```

  書式は `父=<種牡馬名>` `母父=<種牡馬名>` を ` / ` 区切りで `5走距離帯=` の後ろに置く。
  **列は追加しない**（`5走距離帯=` と同じ扱い）。名は競馬ラボ／JRA公式の表記に揃え、取得できなければ
  `父=取得失敗` と書く（**推測で埋めない**）。
  **理由（仮説22）：** 未経験の距離帯・コースの適性は血統でしか埋められないが、その判定入力が
  `predictions.csv` に**存在しない**（母父の記載は187行中1行）。入力がないまま母父ルールを作ると
  判定不能な暫定ルールが増えるだけになる（**仮説17の教訓＝入力が過去/現行データに実在するかを先に確認する**）。
  R38の発火判定と仮説20-d・仮説22の集計入力を兼ねる。**遡及入力はしない。**
- `composite_coef` : 合成係数（クリップ後）
- `coef_breakdown` : **合成係数の内訳**（記録原則10）。書式 `名前値;名前値`（例 `枠0.85;適性1.10;バイアス1.00`）。
  **積が `composite_coef` と一致すること**（許容±0.02。validate.py が ERROR）。
  クリップ（0.7-1.5）に当たって積と一致しない場合のみ notes に `clip` タグを置いて容認する
- `additive_total` : 加算層合計
- `additive_breakdown` : **加算層の内訳**（記録原則10）。書式 `名前±値;名前±値`（例 `R+2.0;騎手+1.0;馬場-1.0`）。
  **符号は必須**。和が `additive_total` と一致すること（許容±0.1。validate.py が ERROR）。
  加算層が空なら `なし`（`additive_total=0` のときのみ）。`R` で始まる項の和は `r_adj` と一致させる（不一致は WARN）
- `r_adj` : 加算層のうちR補正の値（final_score − r_adj ＝ オッズ非依存のモデル素点）
- `final_score` : 最終評価点
- `myomi_score` : 妙味スコア
- `popularity` : 人気
- `win_odds` / `place_odds_max` : 単勝／複勝上限
- `r_value` : R値
- `finish_pos` : 着順（結果後）
- `in_place` : 複勝圏内 1/0（結果後）
- `last_3f` : **上がり3F（秒・結果後）**。`tools/jra_result.py` の出力から全頭転記する（2026-08-03導入・T1）
- `corner4_pos` : **4角通過順位（結果後）**。同上。直線競走（新潟芝1000直等）は4角が無いので空欄
- `notes`

**`last_3f` / `corner4_pos` を持つ理由（T1）：** 『競馬予想_評価ルール.md』第169項が
「着順と上がりの乖離＝負けたが上がり最速は展開不利の好走、**次走加点材料**」と定めているのに、
それを載せる列が無く、不利の反映が主観メモ経由の一本経路しかなかった。
`jra_result.py` は全頭ぶんの上がり3F・通過順を**既に取得している**（列が無かっただけ）。
`pos_gain`（4角位置−着順）は導出値なので列に持たず `analyze.py` で計算する（値の二重管理を作らない）。
2026-08-03に9レース115頭を JRA公式から遡及転記した（さきたま杯＝地方のため公式収録外・取得失敗）。

### bets.csv
- `race_id` / `bet_type`（三連複/三連単/馬連/ワイド等）
- `structure` : 買い目の構造（例 `軸1頭 5→12,13,6,8,2,9`）。
  validate.py はここから馬番を抽出して `predictions.csv` の印と突合するため、
  **馬番以外の数値はラベル語（`軸1頭` `1着` `〜点`）の形で書く**。抽出できないとWARNになる
- `bet_type` : `races.csv` の `券種=` タグと同じ表記を使う（`三連単F` と `三連単` を混在させない）
- `points` : 点数 / `unit` : 単価 / `cost` : 購入額
- `hit` : 的中 1/0 / `return` : 払戻額
- `notes`

### rules_master.csv
- `rule_id` / `rule_name` / `origin_race`（このルールを生んだレース）/ `added_date`
- `status` : 現行 / 暫定(n=10判定) / 包含済(RXX) / 廃止(YYYY-MM)。ゲートで個別チェックするのは現行＋暫定のみ。廃止は行削除せずstatus変更で残す（監査痕跡）
- `direction` : **ルールが馬に与える向き**（`capture` 判定の入力・記録原則11）。
  `上向き`＝特定馬の評価・採用を引き上げる／保全する（R01 R11 R25 R34 等）／
  `下向き`＝特定馬の採用・頭固定を抑制する（R03 R10 R20 等）／
  `双方向`＝構造・配分の分散を要求し特定馬の向きを持たない（R12 R23 R24 R28 R31 R32）／
  `手続き`＝検算・記録・工程順序・シナリオ制約で馬を指さない（R08 R15 R16 R19 R29 R33 等）。
  **`手続き` の行は capture では判定せず、遵守率と validate.py での機械化可否で扱う**
- `scope` : **そのルールをチェックする工程**（2026-08-03導入・T9）。
  `印確定前`（工程9のゲート①）／`買い目`（工程11のゲート②）／`両方`／`振り返り`／`照会`。
  **ゲート②の対象＝`scope` が `買い目`／`両方` の行 ＋ `status=暫定` の全行**（指示v2 工程11の定義）。
  従来はどの行が該当するかを毎回人が判断していたため、`validate.py` がこの定義で
  **買い目のあるレースにゲート②対象ルールの記録が無い場合を WARN で検出する**。
  `fired=0`（該当場面なし）の行も記録する運用なので、**記録が無い＝チェックしていない**と判定できる。
  ルールの `added_date` がレース日より後の行は対象外（遡って適用しない）。

### rule_fires.csv
- `race_id` / `rule_id`
- `fired` : 該当場面があったか 1/0
- `followed` : ルールに従ったか 1/0
- `capture` : **予測方向の当否**（記録原則11。損益と独立の第1軸）。判定は振り返りV4で行う

  判定の問い：**「そのルールに従うことは、3着内という結果に照らして正しい方向だったか」**。
  買い方・券種・損益は見ない（それは outcome）。`followed=0` の行もルール自体の向きを同じ問いで判定する。

  | capture | 定義 |
  |---|---|
  | `的中` | 従うことが結果に照らして正しい方向だった（違反行なら「従っていれば拾えていた」） |
  | `空振り` | 対象馬が3着内に絡まず、従っても従わなくても結果は同じ（**降格根拠にはならない**） |
  | `逆行` | **従うことが結果に照らして逆方向だった。ルールが落とさせた馬が3着内に来た** |
  | `方向なし` | `direction=手続き` ／該当0頭・非対象帯域 ／競走中止で評価不能 |

  - `双方向`（構造分散系）は、分散先のいずれかが3着内なら `的中`、どれも来なければ `空振り`
  - **下向きルールの対象は「馬」でなく「その扱い」。** R03（◎を頭固定にしない）は対象馬が3着内でも
    **1着でなければ的中**（頭で買わない判断が正しかった）。1着なら逆行
  - 「該当0頭」「非対象帯域」は `空振り` でなく `方向なし`（空振りに混ぜるとルールが判定材料を
    持っていたように見える）
  - 2026-08-03に既存68行（`direction≠手続き` の発火行）へ遡及付与済み。手続き系49行は `方向なし`
- `outcome` : **損益寄与**（第2軸）。`効いた` / `逆効果` / `中立` / `違反して失敗` / `違反したが結果OK`。
  `逆効果` の認定には反実仮想の裏取りを要する（『振り返り手順.md』V4が正本）
- `notes`

**2軸に分けた理由：** outcome だけでは「ルールが指した馬が結果に絡まなかった」と
「ルールが正しく指していたが買い方で取り逃した」が両方 `中立` に落ち、ルールの良否が
測れない。R19の降格条件は 2026-08-03 に **`逆行 ≧ 的中`**（capture軸）へ改訂した。

## ルール・傾向データと結果が矛盾したとき

1. **即時には何も変えない。** 矛盾はrule_fires.csvのoutcome（逆効果/違反したが結果OK）として記録するだけ。予想セッション中のルール緩和の根拠には使わない（R19）
2. **改廃はn=10レビューで判定する。** R17適用（生成元レース除外）後の集計で、発火5件以上かつ
**`逆行` ≧ `的中`**（capture軸）のルールを降格候補（現行→暫定）、暫定でさらに悪化したものを廃止とする。
発火5件未満は判定保留（不運と誤りを区別できない）。**`空振り` は降格根拠にならない**（保全コストは出るが害はない）。
**さらに、発火5件以上でも `空振り` が発火の8割を超える場合は判定保留とする**（2026-08-03追加）。
空振りは「従っても従わなくても結果が同じ」であり、ルールが機能した証拠にも逆機能の証拠にもならない。
件数だけで昇格させると**実質未検証のルールが現行化する**。
起点：R20（発火6件・空振り5・的中1・逆行0）が条文上は昇格条件を満たしたが、空振り83%で
「この10レースでR20はほとんど何も判定していない」状態だったこと。R20は**判定保留のまま据え置き**とした。
`direction=手続き` のルールは capture では判定せず遵守率で扱う。
※ 2026-08-02までの判定基準は「逆効果≧効いた」（outcome軸）だったが、中立に68%が滞留して
発動しえないことが第1回較正レビューで判明したため 2026-08-03 に改訂した（P1-3）
3. **「違反したが結果OK」は違反の正当化に数えない。** 結果OKでも違反は違反としてカウントし、ルール側の反証としてのみ扱う
4. **ナレッジファイル（傾向・補正・血統）への反証は、該当ファイルに反証メモとして併記する**（元の記述は消さない）。例：「消しデータ：58kg以上0-0-0-10 ／ 反証：2026北九州記念で該当馬3着（1件）」。反証が2件溜まった傾向は妙味トラック以外での使用を停止し、n=10で存廃判定

## 検証待ち仮説（n=10 到達時に判定）

バックフィル3レースから浮かんだが、母数不足のため暫定扱いの観察。

> **第1回較正レビュー（2026-08-02・n=10）で仮説1〜8を一括判定した。** 各仮説の冒頭に【判定】行を付す。
> 判定なしの仮説9以降は発火・サンプル不足のため次回（n=20）へ持ち越し。

1. **勝ち馬は◎（地力1位）でなく「条件適合1位」に出る**（3/3で◎以外が勝利：○②・無印②・○⑬）。R12（三連単の頭◎○両置き）はこの暫定対策。n=10で◎と○の勝率を比較し、恒久化か廃止かを判定。
   **【判定：支持・R12を現行化】** 10レースの1着馬の印は ◎1／○3／△3／☆1／無印2。◎頭固定なら頭捕捉1/10、◎○両置きで4/10。
   ただし1着馬の最終点順位は 1位・1位・3位・4位・7位・9位・13位（記録済み7レース）で、**点数序列の上位2頭に勝ち馬が入ったのは2/7**。
   「条件適合1位」を印に反映しきれていない構造は未解決のまま残り、Phase 3の係数アブレーションへ送る。
2. **▲の不振**（複勝圏0/2・平均11着）。▲の選定基準（3着内なら頭まで）が機能していない可能性。
   **【判定：不振を確認・原因未特定】** n=11 で複勝1/11(9%)・平均着順8.5・単勝ROI 0%・複勝ROI 31%。
   無印(-)の16%を下回り、○45%・△45%とも整合しない。**▲だけが印の序列から外れている。**
   原因（選定基準か、▲に回る馬の母集団か）が特定できないため、この時点でのルール新設・印の廃止は行わない（R19）。
   Phase 3の「▲・☆の選定基準改訂」を最優先タスクに繰り上げ、係数アブレーションで原因を切り分けてから改訂する。
   **【原因特定：母集団側（2026-08-03・T5）】**
   　印ごとの「レース内 final_score 順位」と人気・R値を並べると構造が出る（記録済み7レース）：

   | 印 | 点数順位（中央値） | 人気（中央値） | R値平均 | 複勝率 |
   |---|---|---|---|---|
   | ◎ | 1位 | 3番人気 | 2.31 | 40% |
   | ○ | 2位 | 3番人気 | 1.95 | 45% |
   | **▲** | **3位** | **4番人気** | **3.11** | **9%** |
   | △ | 4位 | **2番人気** | 2.36 | 45% |

   　**(1) 選定基準は壊れていない。** ▲の点数順位は中央値3位・平均2.7で、○(2.1)と△(4.6)の間に
   　正しく収まっている。「▲に変な馬が入っている」のではない。
   　**(2) 犯人は△との人気の逆転。** 点数順位は ▲(3位) > △(4位) なのに、市場評価は △(2番人気) > ▲(4番人気)。
   　**△の複勝45%は「△が優秀」なのではなく、△に上位人気馬が入っているから。**
   　**(3) ▲＝モデルが市場より高く買った馬が集まる枠。** R値平均3.11は全印で最高（☆3.78に次ぐ）。
   　▲は「点数は3位だが市場は4〜5番手評価」という**モデルと市場の乖離が中程度の馬**の受け皿になっている。
   　**この枠が沈んでいる＝モデルが市場より高く買った馬は負けている**ということ。
   　T4の較正結果（モデル素点 CV Brier 0.1549 < 市場 0.1484）と**同じ診断が独立に3回目の裏取り**をされた。
   　**(4) 有意性：** 真の複勝率が45%（○△並み）なら11回中1回以下は確率1.4%＝**○△より劣るのは有意**。
   　ただし20%（無印並み）なら32.2%で普通の揺れ。**「▲は無印より劣る」とは言えない。**
   　**(5) 打ち手：** 印の選定基準をいじっても直らない（基準は序列どおり動いている）。
   　直すべきは**素点そのものが市場に勝てていないこと**で、これは Phase 3 の係数改訂の課題。
   　進捗は `calibrate.py` の CV Brier が市場の 0.1484 に近づくかで測る。
   　**印の選定理由タグ（当初案）は追加しない**：原因が母集団側と特定できたため、タグを足しても
   　同じ結論しか出ずスキーマが太るだけ。**▲の廃止・統合も行わない**（R19。無印より劣る証拠がない）。
